# 本地覆写规则（priority: 高于 SKILL.md 正文）

本文件是本项目**真正执行的标准**。`lib/prompt.js` + `lib/formats.js` 严格按这里的规则产出提示词；
与 `SKILL.md` 正文冲突时，一律以本文件为准。

> 2026-11-25 大改：从「一条模板套所有商品的产品展示片」改成 **形态引擎 + 全类目兜底**。
> 形态库细节（14 形态 / 18 生活母题 / 40+ 真实麻烦 / 品类优先级）见

## 1. 结构：固定顺序，一段只干一件事

```
【固定参数】→【本条主线】→【创作要求】→【商品识别】→【参考素材】→【本条片子的形态】
→【时间轴分镜】→【节奏参考】→【分镜纪律】→【真实感清单】→【声音设计】→【约束条件】
→【画质风格】→【卖点的画面化写法】
```

- `【固定参数】` 第一行就是**相机身份**（放在最前权重最高），然后是画风和**视频形态**。
- `【本条主线】` 一句话：用什么形态、用一个什么动作证明哪条卖点、最后画面停在什么上。
  分镜写多了容易拍成素材堆，这一句是锚，跟主线无关的镜头一律删。
- `【本条片子的形态】` 写四件事：为什么用这个形态、世界与光线、人物设定、镜头语言。
- 一段只给一种主运镜、一个主信息点；单镜内动作连贯，镜头之间硬切。

## 2. 先定形态，再写分镜（最重要的一条）

**不要写成「产品展示片」。** 观众刷到白底摆拍、逐个展示细节的片子，3 秒就划走。

引擎按商品名 / 品类 / 卖点给 14 种形态打分，取最合适的；重抽在前 3 名里轮换。
形态一律自带 8 个节拍的动作、机位、声音、禁忌 —— 写提示词时是「填形态」，不是「自由发挥」：

| 场景 | 用什么 |
|---|---|
| 用户指定了形态（`formatKey`） | 强制用它，不许换 |
| 用户选了「AI 自由构想」（`formatKey='free'`） | 用 `conceive()` 构想出的生活场景 + 真实麻烦，8 拍顺着这条情节走 |
| 其余 | `pickFormat()` 打分第一名 |

**全类目兜底**：`lib/product.js` 的形态库认不出来的商品，由 `CAT_HINTS` 按名字推品类
（泳装→穿搭、洗面奶→美妆、美缝剂→家居、鱼缸过滤器→宠物、渔线轮→运动…），
再由 `TROUBLE_BY_CAT` 给一条该品类的兜底麻烦。**任何商品进来都不许掉进「通用场景」。**

## 3. 时长与节奏：镜头数跟片长走，百分比铺满全片

- **镜头数不是固定 8 个**：15 秒 8 镜、10 秒 6 镜、5 秒 4 镜（`FLOW_PLAN`）。
  8 拍硬塞进 5 秒＝每镜 0.6 秒，AI 视频里切不出来，写进提示词只会让模型乱跳。
  压缩不是丢段落：同一组里的动作与落点合并成一句，**卖点一条都不少**。
- 时长只写一次（用户选的那一档），并补一句「平台若只支持固定档位，就用最接近且不短于它的档位，
  百分比段按整条片长等比铺满，不砍段落、不截断」。
- 每镜时长按 `片长 ÷ 镜数` 算出来写（15s≈1.9、10s≈1.7、5s≈1.3），**不许写死「1.6-2 秒」**。
- 每一镜都有独立的百分比区间，首镜从 `0%` 起、末镜到 `100%` 收，段与段首尾相接不留缝。
- 每个节拍都有一句「落点」（这一镜要让观众得到什么）：

| 节拍 | 作用 | 落点 |
|---|---|---|
| `0%-11%` 开场钩子 | 爆点（结果先行 / 强反差 / 悬念 / 极端特写 / 直接亮全貌） | 第一帧就有让人停下来的看点 |
| `11%-21%` 交代场景 | 亮出环境、人物、商品同框 | 一眼看懂：什么地方、谁在用、用的什么 |
| `21%-35%` 卖点一 | 细节特写证明第一条卖点 | 卖点被一个可见的细节证明 |
| `35%-48%` 卖点二 | 一次真实操作 | 卖点落在动作上 |
| `48%-63%` 卖点三 | 核心体验在动态里成立 | 第三条卖点在动作里成立 |
| `63%-76%` 情节推进 | 有人加入 / 场景变化 / 出现反转 | 情节往前走一步 |
| `76%-91%` 结果兑现 | 状态明显变好 | 结果清楚可见，不用解释 |
| `91%-100%` 定格收尾 | 商品留在画面中心，背景还在动 | 最后半秒主体清晰、画面稳定 |

- 表里是 15 秒 8 镜的基准切分；6 镜 / 4 镜时按 `FLOW_PLAN` 合并相邻节拍，百分比重新算，仍然铺满 0%-100%。
- 全片不许连续两镜静止摆拍，不许长镜头、缓慢推拉的空镜、匀速平铺。

### 3.1 开场钩子按「形态」精确匹配

`HOOK_FORM_RULES` 里一张表：耳机、吸尘器、风扇、加湿器、挂烫机、手机、充电宝、键盘、地毯/床品、
窗帘、厨具、口红、护肤、鞋、包、零食、积木、手办、猫窝、冰箱贴、鱼缸、花洒…各有各的爆点。
命中时**直接覆盖第一镜的动作**——「耳机戴上噪音被抽走」比「一次干脆的操作」具体得多。
没命中才退回形态自己的开场；情景段子的开场会用 `{trouble_setup}` 填进该品类真实的小麻烦。

## 4. 分镜纪律（不满足就会出废镜）

1. **商品或它的使用结果必须在前 3 秒内出现**（可以只是局部特写），不要等到中段才亮货。
2. 每镜只承担**一个主动作**；相邻两镜至少在「景别 / 机位角度 / 人物关系」里变一项。
3. **一个动作链只在一镜里完整发生**：前一镜不得提前出现动作完成后的状态（前镜已拆包装、后镜又拍拆包装＝穿帮）。
4. 禁四类拍不出来的写法：
   - ① 两个主体精确配合的交互（对抛、击掌、碰杯特写）
   - ② 心理描写（"犹豫""意识到""想起了"）
   - ③ 否定式动作（"没接住""不理他"）
   - ④ 一镜内三步以上的手部动作链
   遇到就换成"实际发生的画面"，或拆成两镜。
5. 有台词时，情绪按**三拍**写：触发 → 身体先反应 → 面部克制。不写"他很惊讶""很满意"这类终态词。
6. 最后两镜给一次**自然的行动引导**（手指向画面下方、把商品递向镜头），不喊话、不出现"点击下方"字样。

## 5. 真实比例：最高优先级硬约束

AI 最常见的错误是**把商品拍成「比人还大的杯子/耳机」**。每一类都必须给现实尺寸锚点，并在三处同时写：手部段、人物段、【约束条件】。

- 与手同框：不超过手掌/小臂应有的比例
- 与人同框：**绝不能比人的头、上半身更大**
- 商品单独出镜可以特写占满画面，但必须说明「这只是镜头推近，不代表实物被放大」
- 人物在画内时商品约占画面高度 **25%-40%**；收尾镜头推近、人物退出后才回到 **60%-70%**

尺寸锚点表：

| 品类 | 锚点 |
|---|---|
| 杯/壶 | 高 20-26cm、直径 6-8cm；单手握持约一只手掌长，不高于小臂 |
| 锅具 | 直径 24-32cm、深 8-12cm；碗盘 15-25cm；刀具 25-33cm |
| 手机 | 长 15-16cm（约一只手掌长） |
| 耳机 · 真无线/入耳 | 盒 5-7cm 可单手包住；单只约 3cm，正好贴合耳廓 |
| 耳机 · 头戴 | 耳罩直径 7-9cm、头梁展开 15-18cm，与真人头围一致（成人头宽 15-16cm） |
| 耳机 · 有线 | 本体 2-3cm、线控 5cm、线长 1.2m，线材不粗于充电线 |
| 护肤 | 瓶 30-100ml、高 8-15cm，可单手握住；口红 8cm |
| 服饰 | 按真人尺码；鞋 24-30cm；帽围 55-60cm |
| 家居 | 抱枕 45-50cm；台灯 40-60cm |
| 五金 | 握柄 10-15cm 贴合手掌，不出现握不住的巨型工具 |

## 6. 品类使用逻辑：必须符合真实操作顺序

**不能所有品类共用一套话**。写错了模型会做出荒谬动作（典型：给耳机写「先取下杯盖再喝」）。

| 品类 | 使用逻辑（写进【约束条件】） |
|---|---|
| 杯壶 | 要开盖才能喝的，先完整取下盖子放在桌面同一位置再喝；喝的时候杯上、手上都没有盖子 |
| 厨具 | 先就位再操作（砧板放稳、锅具上灶），带盖的先完整打开 |
| 数码/耳机 | 耳机盒先开盖再取放耳机；插头插到底、拔到位；不出现「没开盒就拿出耳机」「耳机悬空显示」 |
| 服饰 | 先穿好、拉链扣好再展示活动；鞋先穿上脚再走动 |
| 美妆 | 先开盖再取用，用完盖回；按压类先按压再展示质地 |
| 食品 | 先拆封再取食，不出现「隔着包装吃」 |
| 家居 | 先展开或组装到位再使用，用完复位 |
| 家电 | 先通电 / 装好再启动；有线材的先理顺，不出现「插着线满屋拖着走」 |
| 工具 | 先到位再启动，用完归位；带安全锁的先解锁 |
| 母婴 | 先拆封或清洁到位再给婴儿使用，动作始终轻柔 |
| 宠物 | 先让宠物自己靠近闻一下再使用，不强行按住 |
| 户外 | 先搭好 / 穿戴到位再进入活动，风大的场景要拍到布和头发在动 |
| 珠宝眼镜 | 戴上之后再展示，扣好 / 推好镜腿；不出现悬空漂浮的首饰 |

## 7. 耳机专项（坑最多，单独列）

耳机是「戴上就看不见」的商品，模型为了满足「商品清晰可辨」会把耳机画得比头还大。**必须按子类分开写**：

| 子类 | 识别关键词 | 佩戴写法 |
|---|---|---|
| 真无线/入耳 | 默认、无线、TWS | 先开盒、取一只戴右耳（耳塞贴合耳廓），戴好后侧头示意；**绝不能画大、挂在耳外或悬空贴在耳侧** |
| 头戴 | 头戴、耳罩、包耳、over-ear | 耳罩完整包住双耳、头梁贴合头顶；耳罩 7-9cm，**不能比头还大** |
| 有线 | 有线、线控、3.5 | 插头插入手机，戴上耳机、线材自然垂落不缠绕 |

收尾**禁用「屏幕」**（耳机没有屏幕，写「屏幕微亮」模型会硬加一块屏）：
真无线 → 盒盖敞开、另一只留在盒内、指示灯微亮；头戴 → 取下静置桌面、耳罩朝上；有线 → 与手机并排静置、线材盘放不打圈。

## 8. 字幕与台词：由用户勾选，不再写死在底层

任务参数 `noText` / `noVoice`，默认都是 `true`（保持一直以来的成片风格）：

| 字段 | 默认 | 勾上（true） | 取消勾选（false） |
|---|---|---|---|
| `noText` | 不出字幕 | 画面内不出现任何可读文字、字幕、价格、水印、贴纸 | 允许 1-2 行干净短句，不用花字，不遮挡商品与人物面部 |
| `noVoice` | 不出台词 | 全片无口播、无旁白、无人声；形态自带的人声方案换成 `soundNoVoice` 版本 | 按形态决定：口播/街采/段子/教程可以说口语短句，一镜不超过一句 |

**必须避免自相矛盾**：勾了「不出现台词」时，声音段不能同时出现「同期人声对白」和「全片无人声」——
有人声的形态（ugc / skit / interview / tutorial）都配了 `soundNoVoice`，改用那一版。

## 9. 固定禁令（条件化，全品类通用）

- **文字**：`noText=true` → 无字幕、标题、卖点字、价格、水印（商品自带 Logo 与包装印字除外）；`false` → 只允许干净短句。
- **声音**：`noVoice=true` → 无对白、无口播、无人声、无旁白，只留 BGM + 环境底噪 + 商品真实音效；`false` → 口语短句，不念参数、不念价格、不喊口号、不用"最"字。
- **穿模/穿帮**：手指穿过商品、商品变形、第二个同款、影子与光源不一致、色温跳变，全部禁止。
- **一致性**：形态、比例、颜色、Logo、材质、包装文字、配件数量全片与 @图片1 严格一致。
- **节奏**：不允许连续两镜静止摆拍、长镜头、缓慢推拉空镜、匀速平铺。
- **开场**：要有抓人的看点，且必须跟这件商品真实相关（不能出现产品自己飞起来这种胡编）。

## 10. 第三方技法融合（2026-11-25）

`lib/craft.js` 从两个公开仓库提炼技法，**按需注入**，不堆成新禁令：

| 来源 | 许可 | 提炼内容 |
|---|---|---|
| `LearnPrompt/awesome-seedance` | 策展 CC BY 4.0 / 代码 MIT | 参考图身份锁（继承 / 不继承 / 跨镜）、手持 UGC 相机缺陷词、第一人称非空开场与硬切声明、美食 ASMR 声音按动作顺序、穿搭逐件锁、过程类不变量 + 空间顺序、广告 hero frame |
| `dexhunter/seedance2-skill` | MIT | 高级运镜术语表、景别词汇表、避坑清单 |

- 注入点三处：`buildPrompt()` 的【参考素材】（身份锁四段）、【真实感清单】（相机质感 / 设备感 / 形态技法 / 避坑）、
  `buildDoubaoBrief()` 的【来自 Seedance 技法的补充要求】；`buildScript()` 同步补一行「设备感」，验收时脚本与提示词对得上。
- **台词类技法只在 `noVoice=false` 时注入**，任务书里那半句「台词焊在对应那一拍上」同样受开关控制，
  否则会出现「台词：全片无台词」和「台词焊在那一拍上」并列的自相矛盾。
- 这些是技法建议，不覆盖 §1–§9 的硬规则；原文留档 `_refs/`（不参与运行），提炼明细见 `references/third-party-craft.md`。
- 新增形态时必须补 `FORMAT_CRAFT` / `GEAR_ERA` 条目——`node _t/check-prompt.js` 会检查死键与漏配
  （形态改了名但技法表没跟，代码不报错、规则静默失效，靠人眼看是发现不了的）。

## 11. AI 代写：和本地模板同构，只换作者

`buildDoubaoBrief()` 生成的是「写作任务书」，不是另一套标准。硬要求：

| 必须一致 | 说明 |
|---|---|
| 镜头数 | 与本地同一套：15s→8、10s→6、5s→4；每镜秒数按 `片长÷镜数` 给区间 |
| 参考素材 | 有图时必须写清 `@图片1` 是基准、`@图片2` 起是同款其他角度；无图时明确说「这次没有参考图」 |
| 一致性锁 | 输出格式里要求最后写一段 `【一致性锁】`；商品结构与 @图片1 严格一致 |
| 真实感清单 | 光不完美 / 场景有生活痕迹 / 人有反应过程 / 动作有重量，四条要写进任务书 |
| 分镜纪律 | 前 3 秒亮货、一镜一动作、动作链不跨镜、四类禁写，与本地逐条对齐 |
| 第三方技法 | 任务书必须有【来自 Seedance 技法的补充要求】段：参考图三段锁、材质要具体、运镜景别词表、避坑；台词类技法跟 `noVoice` 走 |
| 编号 | 硬性要求必须 1..14 连续，不跳号（跳号会让模型漏读） |
| 用途说明 | 「它是做什么的」两边必须同一句：`p.purpose`（商品级覆写）优先，没有才查 `PURPOSE_HINTS`。两边各取一套就会出现「本地模板说是婴儿睡袋、任务书说是户外装备」 |
| 开场钩子 | 任务书里的候选形态必须走过 `refineProduct` 纠偏，不能把睡袋推荐成旅拍 |

写回来的文本经 `cleanDoubaoPrompt()` 去围栏/客套，再由 `isUsableDoubaoPrompt()` 判断（太短、拒答、
没有镜头词都算失败），失败**自动回退本地模板**，不卡任务。

## 12. 改代码的约定

1. 改提示词规则 → 同时改 `lib/prompt.js`（四个出口：`buildPrompt` / `buildScript` / `buildClips` / `buildDoubaoBrief`）和本文件。
   纯技法类的增删改在 `lib/craft.js`，改完仍要跑一次 `check-prompt.js` 的技法段。
2. 改形态 / 母题 / 麻烦库 / 品类 → 只改 `lib/formats.js`，然后跑 `node _t/gen-formats-doc.js > skills/seedance-prompt/references/video-formats.md` 重新生成文档。
3. 加了新品类 → 四处都要跟：`CAT_ORDER`（形态优先级）、`CAT_HINTS`（兜底识别）、`TROUBLE_BY_CAT`（兜底麻烦）、`PURPOSE_HINTS`（它是做什么的）。
   `PURPOSE_HINTS` 只写「怎么用」，不写卖点；名字里看不出来才轮到卖点兜底，否则「保温」这种词会把任何商品判成杯子。
4. 加了新的开场钩子 → 改 `HOOK_FORM_RULES`，按 form key 写（`beauty-lip`、`shoes`、`toy-block`…），
   越具体的规则放越前面；商品级麻烦用 `REFINE` 的 `trouble` 字段覆写。
