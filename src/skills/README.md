# 提示词技能库（skills/）

这里放的是「提示词写法」的权威依据。程序里的 `lib/prompt.js` + `lib/formats.js` 就是按它落地的。
**运行时不读取本目录**（纯文档），但改规则时两边必须同步，否则文档会骗人。

## 融合到程序里的部分（2026-11-25 形态引擎版）

| 原则 | 落地位置 |
|---|---|
| 先判断「这件商品怎么被用到」，再决定拍法 | `lib/formats.js` 的 `rankFormats()` → `pickFormat()`，14 种形态打分取 top3 轮换 |
| 不套模板，按商品现编生活场景 | `conceive()` + `buildFree()`：18 个生活母题 × 40+ 真实麻烦 |
| 全类目兜底 | `CAT_HINTS`（认不出商品时按名字推品类）+ `TROUBLE_BY_CAT`（每个品类一条兜底麻烦） |
| 固定参数单独列（时长/比例/画幅/相机身份/画风/形态） | `buildPrompt()` 的【固定参数】段 |
| 正文公式：时间 → 机位 → 主体 → 动作 → 场景 → 光影 | 【时间轴分镜】8 个百分比节拍，每拍一句「落点」 |
| 一个镜头只给一种主运镜 | `CAMERA_SETS`（fast / handheld / slow 三套 × 8 机位），按形态能量选 |
| ~~13–15 秒 3–4 个阶段~~ **改为快节奏多镜** | 电商带货要「前 3 秒抓人」。镜头数跟片长走：15s→8 镜、10s→6 镜、5s→4 镜（`FLOW_PLAN`），每镜秒数=片长÷镜数，硬切衔接 |
| ~~动作缓慢连续、写过渡~~ **改为单镜内连贯、镜头间硬切** | 每镜动作做完做干脆，但不允许连续两镜静止 |
| 开场 3 秒按「形态」给专属爆点 | `HOOK_FORM_RULES`：耳机降噪抽走噪音、吸尘器吸口掠过地面、窗帘拉开光灌进来、口红划一道显色…命中即覆盖第一镜 |
| 同一大类里不同商品，麻烦要分开 | `REFINE` 的 `trouble` 字段：吸尘器是「地上一层毛」不是「饿但不想凑合」，猫窝是「它不睡」不是「饿了一天」 |
| 分镜可拍性 | 【分镜纪律】：前 3 秒亮货 / 相邻镜变一项 / 动作链单镜完成 / 四类禁写 / 情绪三拍 / CTA 手势 |
| 情绪外化、靠身体信号 | 人物段只写姿态与动作，不写"他很惊讶"这类终态词 |
| 约束条件固定一组稳定性要求 | 【约束条件】一致性、真实比例、人体、使用逻辑、连续性、文字（受 `noText` 控制） |
| 声音设计单独写 | 【声音设计】段；`noVoice` 时用形态的 `soundNoVoice` 版本，避免自相矛盾 |
| 画质风格词放句末 | 【画质风格】段 |
| 时长只写一次，正文用百分比切分 | 【固定参数】写用户选的档位并注明「平台档位不同时按百分比铺满」；分镜段只用 0%-100% |
| 一句话主线锚住全片 | 【本条主线】：什么形态 + 哪个动作证明哪条卖点 + 最后停在什么上 |
| 认错品类要能改回来 | `CAT_OVERRIDES`（按用途改判品类）+ `REFINE`（整段覆盖场景/尺寸/动作）+ `buildPlan()` 里的兜底（以前漏了，正文会写成「通用商品」） |
| 用户只写一句也能出片 | `buildOtherRequest({expand:true})`：补 8 拍镜头结构 + 约束条件 + 画质风格；关掉则原样发用户那句话 |
| 参考图分「必须继承 / 不得继承 / 跨镜保持」三段写 | `lib/craft.js` 的 `refLockLines()` → 【参考素材】段；只当商品样本，不当构图模板 |
| 真实感落到可执行的拍法，不写一句「真实」 | `craftLines()` 按形态能量给相机缺陷词（抖动/对焦呼吸/曝光浮动）、按形态给设备年代词、给该形态专属技法与避坑 |
| 运镜与景别给词表，机位描述才具体 | `ADV_MOVES` / `SHOT_SIZES`，快形态与广告形态按需注入，每拍仍只给一种主运镜 |

## 重抽怎么变

- 形态：`pickFormat(input, variant)` 在前 3 名里顺延，第 2 次重抽自动换一种拍法（用户手动指定形态时不换）。
- 变体：`VARIANTS` 4 套（标准 / 逆光 / 俯拍 / 低机位），换光线、场景、人物服装、每拍主运镜。
- 自由构想：`conceive(input, variant)` 的生活母题池按 `variant` 轮换，场景也跟着换。

## 改东西的顺序

1. 改形态 / 母题 / 麻烦库 / 品类兜底 → 只改 `lib/formats.js`，然后重新生成文档：
   ```bash
   node _t/gen-formats-doc.js > skills/seedance-prompt/references/video-formats.md
   ```
   `video-formats.md` 全部由脚本渲染（含 §3.1 语义覆写表、§3.2 商品级纠偏表、§8 收尾细节、§9 用途判定），**别手改**。
2. 改提示词结构 / 纪律 / 文案 → 改 `lib/prompt.js` 的四个出口 + `OVERRIDE.md`。
3. 回归（两条都要跑）：
   ```bash
   node _t/cover.js        # 69 个全类目样本，要求「未识别品类 = 0」
   node _t/check-prompt.js # 252 组抽样 + 30 组全形态矩阵 + 8 组极端输入，0 错误才算改完
   ```
   `check-prompt.js` 查的是会真出事的东西：占位符残留（`{sell1}` 会被原样发给豆包）、
   小节缺失、镜头数与片长不匹配、百分比断档、AI 任务书编号跳号、
   **用途说明两边不一致**（本地模板说「婴儿睡袋」、AI 任务书说「户外装备」这种），
   以及**技法表失配**（形态改名后 `FORMAT_CRAFT` / `GEAR_ERA` 没跟、死键、漏配设备感——这类问题代码不报错，
   只会让那几条真实感要求静默消失）。

## AI 代写不是另一套标准

`buildDoubaoBrief()` = 同一套硬要求 + 让豆包来写分镜正文。镜头数、参考素材说明、一致性锁、
真实感清单、分镜纪律、用途说明逐条对齐；第三方技法以【来自 Seedance 技法的补充要求】整段交代过去，
台词类技法受 `noVoice` 控制。写回来的东西不达标会自动回退本地模板，不会卡住任务。
细节见 `seedance-prompt/OVERRIDE.md` §11。
