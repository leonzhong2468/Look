## 二、进程与线程模型

```
主进程（main.js）
 ├─ BrowserWindow(mainWindow) ── 渲染层（index.html + renderer.js + task-ui.js）
 ├─ BrowserWindow(workerWin) ─── 离屏，跑任务用
 ├─ WebContentsView(账号A..N) ── 每个挂在自己的 persist:<id> 分区
 ├─ Tray ─────────────────────── 托盘
 └─ 定时器：keepAlive(45s) / rebuildTrayMenu(15s) / 登录监控(按账号)

渲染进程
 └─ 只能通过 window.api.* 与主进程通信（contextIsolation: true）

页面进程（每个 WebContentsView 一个）
 └─ 注入探针 window.__DB（豆包）/ window.__GEN（通用），由驱动 executeJavaScript 调用
```

**为什么这样分**：登录态隔离靠 Electron 的 `persist:` 分区，一个账号一个分区 = 天然多开；切号不重载页面，所以不丢状态、不掉登录。

## 三、任务生命周期

```
tasks:create  → 写 tasks.json，状态 draft
tasks:start   → 挑一个空闲在线账号 → leaseView() → 视图移到 workerWin
              → pipeline.runTask / runOtherTask
              → 每步 pushToRenderer('task:update')
              → 完成后 releaseView()，状态 review / done
tasks:approve → 人工验收通过
tasks:rerunVideo → 带着修正意见重跑（沿用白底图与提示词）
```

任务对象的关键字段：

```js
{
  id, title, status,            // draft|queued|running|review|done|failed|paused
  mode,                         // 'ecom' | 'other'
  step,                         // 当前步骤 key（用于步骤条高亮）
  accountId, providerId,
  params: { images, name, formatKey, videoKind, prompt, ratio, duration, noText, noVoice, noAmbient, extra },
  outputs: [{ kind, path, label, at }],
  video, image, promptText, error, createdAt, finishedAt
}
```

## 四、「想改 X」对照表

| 想改 | 动这里 | 备注 |
|---|---|---|
| 界面配色 / 圆角 / 字号 | `style.css` 顶部的 `:root` 与 `[data-theme=dark]` | 用变量，别硬写颜色 |
| 左侧导航项 | `index.html` 的 `.rail` + `renderer.js` 的 `setView` | 新增视图要加 `.view` 容器 |
| 新建任务表单字段 | `index.html`（`#paneEcom` / `#paneOther`）+ `task-ui.js` 的 `doCreate` | payload 字段要和 `lib/ext.js` 的 `tasks:create` 对齐 |
| 步骤条文案 / 步数 | `task-ui.js` 的 `ECOM_STEPS` / `OTHER_STEPS` | key 要与 pipeline 里设置的 `t.step` 一致 |
| 提示词风格 / 分镜 | `lib/prompt.js` | 四段骨架别拆；改完跑 `_t/check-prompt.js` |
| 某件商品被认错、麻烦不对、用法写错 | `lib/formats.js` 的 `REFINE` / `PURPOSE_HINTS` | 先加商品级覆写，实在不行再改品类表 |
| 形态 / 母题 / 麻烦库 | `lib/formats.js` | 改完必须重新生成 `video-formats.md` |
| 商品品类场景 | `lib/product.js` 的 `PRESETS` | 加一条 = 加一个品类 |
| 商品形态动作链 | `lib/product-forms.js` | 一种形态一条真实动作链，别套模板 |
| 其他视频四种类型 | `lib/prompt.js` 的 `OTHER_KINDS` | `needRef` 决定是否强制上传参考图 |
| 白底图裁剪阈值 | `lib/fit.js` 的 `WHITE` | 246 → 更小更严格 |
| 豆包页面选择器 | `lib/page-agent.js` | 只影响豆包 |
| 其他平台选择器 | `lib/gen-agent.js` | 只影响通用平台 |
| 加一个 AI 平台 | **不改代码**，界面里加 | 存到 `userdata/providers.json` |
| 加一个 IPC | `main.js` 或 `lib/ext.js` 的 `ipcMain.handle` + `preload.js` | 两处必须同步 |
| 托盘菜单 | `main.js` 的 `buildTray` / `rebuildTrayMenu` | |
| 登录态判定规则 | `main.js` 的 `checkStrongCookie` | 用 Cookie 域名，不写死豆包 |
| 关于页 | `renderer.js` 的 `renderAboutStage` | 纯文案，无图片资源 |

## 五、驱动接口（加平台适配时看这个）

`lib/driver.js`（豆包）与 `lib/generic-agent.js`（通用）必须暴露**同名方法**，流水线才能不改就跑：

| 方法 | 作用 |
|---|---|
| `openNewChat()` | 开一个新对话 |
| `checkLogin()` | 是否已登录 |
| `uploadImages(paths)` | 上传图片（走 file input / 剪贴板） |
| `typePrompt(text)` | 输入提示词 |
| `send()` | 点发送 |
| `autoConfirm()` | 处理平台弹的「确认生成」 |
| `waitResult(kind)` | 等出图 / 出片，返回结果信息 |
| `grab(items)` | 把成品下载到本地 |
| `readLastReply()` | 取最后一条回复原文（给「AI 代写提示词」用） |

加一个平台的顺序：
1. 先试通用驱动（很可能直接能用）
2. 不能用 → 在 `gen-agent.js` 里补选择器
3. 还很特殊 → 抄 `generic-agent.js` 写一个新驱动，在 `pipeline.makeDriver` 里按 `kind` 分发

## 六、代码约定

- **不引入新依赖**。只用 Electron 自带能力 + Node 原生模块。
- **不打 asar**。用户要能改 `resources/app/`。
- **不要改** `contextIsolation` / `nodeIntegration`。
- 改完 JS 必须 `node --check`。
- 中文注释，写「为什么」，不写「是什么」。
- 不要动 `userdata/` 做测试；要测就新建测试账号。
- 一次改一块，改完重启验证。

## 七、调试技巧

| 想干什么 | 怎么做 |
|---|---|
| 看渲染层报错 | 顶栏虫子图标 / `Ctrl+Shift+I` |

| 连 CDP 调试真实进程 | 启动时加 `--remote-debugging-port=9333`，再 `curl http://127.0.0.1:9333/json/list` |
| 单测提示词 | `node -e "console.log(require('./lib/prompt').buildOtherRequest({videoKind:'t2v',prompt:'测试'}).request)"` |
| 看平台注册表 | 读 `userdata/providers.json` |
| 看任务数据 | 读 `userdata/tasks.json` |
